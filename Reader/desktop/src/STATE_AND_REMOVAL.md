# Desktop reader state and EPUB removal

This development host stores schemaVersion 1 reader snapshots in `library/reader-state/<editionId>.json`, outside `library/editions/<editionId>/`. State contains a publication-bound locator, preferences, bookmarks and highlight/note annotations. Edition identity is the imported EPUB's SHA256. The shared renderer receives `input.state` and emits `stillleaf-reader-event` snapshots with `type: "state"`; `exportState()` supplies a final close-time snapshot.

The reader BrowserWindow has no preload, Node integration or privileged bridge. The main process installs a listener in the trusted top-level reader document before opening the book and polls serialized state. It separately checks edition identity, schema version, revision, total bytes, list lengths, text limits, preference ranges and locator membership in the edition manifest. Library IPC additionally requires the exact Library window, main frame and URL. Publication scripts remain disallowed by the renderer/host security boundary; state messages cannot name filesystem paths or request arbitrary host operations.

Saves are serialized per edition. Older revisions cannot overwrite newer ones. Writes use a private temporary file, file sync and rename, with the previous valid file retained as `.bak`. A damaged primary can recover from its backup; the damaged original is retained under a `.recovery-...` name before the next successful save. If both copies are damaged, reading does not silently replace them with empty annotations. State is local plaintext; disk encryption belongs to the operating system. File sync/rename is not a claim of transactionality with the journal or resilience to every filesystem/power-loss failure.

The Library's Remove action explains both choices:

- **Keep an EPUB copy…** asks for an explicit save location outside managed storage, creates a new file without overwriting, streams the complete EPUB while checking SHA256, then requests OS Trash for only the edition's app-managed directory.
- **Move managed files to Trash** requests OS Trash for that same edition directory, including its managed EPUB and extracted resources. The user's original source file is never deleted.
- **Cancel**, including cancelling Save, leaves the Library book and files unchanged.

A reader for that edition is saved and closed before removal. Reader state and a retained metadata record in `library/retained/<editionId>.json` survive removal, so the journal Library card, completion, rating, review and reading records remain available without retaining reader assets. This is not a fabricated external-reader connection; adapter matching remains separate. Cards with no managed EPUB offer Import to read and omit the managed-file removal action.

The retained record is written before moving assets. A failed Trash operation leaves the Library entry in place and reports the failure; if an EPUB was already exported, that successful copy remains and its path is reported. No permanent-delete fallback is used. Failed exports never trigger Trash. Tests inject a fixture Trash provider that moves only synthetic directories; actual Windows Trash behavior and platform dialogs remain to be verified on Windows hardware. The separate SQLite journal remains outside the managed edition directory and is never deleted by this operation. Native Mac uses its existing journal; this module does not replace that store.

`reader-state.cjs` owns state validation/persistence, `removal.cjs` owns copy/Trash coordination, and `main.cjs` owns trust checks/dialogs. The unit tests cover persistence, backups, forged paths, retained annotations, original preservation, no overwrite and Trash failure. Verified hidden Electron 44.4.5 on macOS covers Library-first opening, explicit reading, annotation/DOM-range persistence, immediate same-edition reopen, app restart, network denial with a positive control, Cancel, Keep export and fixture-only Trash. The shared renderer was built by its owning worker; no concurrent build was run here. No Windows execution is claimed.
