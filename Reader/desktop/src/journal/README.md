# Local journal foundation

This is a separate SQLite journal outside managed EPUB assets. No book removal path deletes it. Schema version2 uses STRICT tables, foreign keys, WAL and FULL synchronization; compound changes are transactions. Unknown/newer schemas fail closed. `backupTo(absolutePath)` uses SQLite's online backup API and verifies integrity, refusing overwrite. The app-private parent directory must be trusted; filesystem permissions on Windows are inherited from its app-data ACL.

Runtime verified locally: Node22.18.0 / SQLite3.50.2 and Electron44.4.5 main process / Node24.21.0 / SQLite3.53.4. No native addon or new dependency is required. Node22 emits its experimental SQLite warning. These are macOS executions, not Windows runtime or packaging validation.

Existing version1 databases are integrity-, foreign-key-, and shape-checked before migration. A uniquely named sibling `.pre-v2-<uuid>.sqlite` snapshot is created with `VACUUM INTO` and independently validated as version1 before the transactional schema upgrade. `migrationBackup` exposes its path; failed upgrades preserve the original schema and backup. Fresh databases start at version2. This automatic SQLite upgrade is separate from the explicit prototype JSON import below. Backups are retained; rotation is not implemented.

`new JournalStore(absoluteDatabasePath, {timeZone = "UTC"} = {})` from `store.cjs` exports synchronous methods except `backupTo`:

- `attachEdition({editionId,title,creators,bookId?,recordedAt})` returns `{created,book,editionId}`. Default journal identity is `epub:<SHA256>`; an explicit existing bookId associates another edition. Titles never merge identities.
- `createBook({id?,title,creators?,source?,recordedAt})`; `getBook(id)` / `listBooks()` return `book_id,title,creators,source,recorded_at`; list also includes `editionIds`.
- `addManualEntry({id?,bookId,day,timeZone,pages?,minutes?,position?,note?,recordedAt})` returns `{created,entry}`; `manualEntries(bookId?)` returns stored dated rows. Position never creates pages or minutes. A supplied zero-page, positive-minute entry counts its minutes. There are deliberately no invented session start/end timestamps.
- `markFinished({bookId,clickedAt,id?})` returns `{created,event,celebrationToken}`. Repeat clicks, including a book already finished with an unknown imported date, create no event or token. Only a new explicit click supplies its finish time. `recordCompletion`, `editCompletionDates`, `completion`, `timeline` retain manual-over-import authority and one current completion per book.
- `setRating({bookId,value,recordedAt})`: null clears,0–5 quarter stars (including0). `setReview({bookId,text,recordedAt})`: trims, empty clears,50000 graphemes maximum. `rating(id)`, `review(id)` expose current values.
- `setGoals({daily?,annual?,recordedAt})` saves both atomically. Daily shape `{effectiveDay,unit,minutes,pages?}`; annual `{year,books}` with null disabling annual target. `dailyProgress(day, timeZone)` combines dated manual entries with counted tracked seconds converted to minutes; `annualProgress({year,timeZone,now})` counts unique journal books with a known authoritative finish in that civil year and no later than now. Default daily goal20 minutes; goal effective-day history preserved.
- `appendTrackingBatch({intervals,events})` atomically persists a synchronous tracker checkpoint. Identical interval/event IDs are idempotent; conflicting IDs, overlapping intervals, changed session identity, unknown books, and supplied page/locator fields are rejected. A failed transaction leaves all previous records intact. Batches are bounded to10000intervals/20000events. Positive interval durations cannot exceed366days or their wall-clock span by more than2seconds.
- `trackingIntervals(bookId?)` returns `{id,sessionId,bookId,source,mode,timezoneId,start,end,duration,disposition}` records, with ISO start/end, duration in seconds and disposition `credited` or `uncertain`. `trackingWatermark(bookId?)` returns the latest durable ISO end or null.
- `close()` closes database. Caller supplies all record/click times; no guessed dates in the core API. Trusted host must validate IPC and supply actual clock for user clicks. Store/db internals must never be exposed to a renderer.

`importPrototypeFile(store,absoluteFile,{recordedAt,timeZone})` in `migration.cjs` explicitly imports version1 prototype JSON (max16MiB). It retains exact bytes and unknown fields in a provenance backup inside SQLite, never writes the prototype, keeps position/pages separate, and imports Finished status with an unknown finish date. SHA256 source identity and stable namespaced row mappings make repeat import idempotent. Changed known records cause an atomic conflict error requiring future resolution UI. Migration is never automatic.

Behavioral authority: BooksCore/BookHistory.swift and ReadingGoals.swift; AppModel's explicit completion semantics; full reader plan's Windows migration section. The original11 foundation fixtures cover restart, year/timezone boundaries, source priority, goal rollback, quarter ratings, backup no overwrite, prototype conflicts and unknown schema preservation.

Run from Reader/desktop: `node --test src/journal/test/*.test.cjs`. Run same suite with the installed Electron executable and `ELECTRON_RUN_AS_NODE=1`; `runtime-probe.cjs` also runs in a no-window Electron main process.

Remaining parity: no activity correction UI, book merge graph/reread episodes, full native archive interchange, migration preview/conflict-resolution UI, automatic backup rotation, or Windows hardware/installer verification. This database backup is not a complete archive of EPUB files. Manual entry editing/deletion is not yet surfaced. Exact source backup is retained for unsupported prototype fields such as total page count/status.

## Desktop host integration

The existing main process now opens `journal.sqlite` next to its private Library directory and registers recovered/imported editions. Its Library snapshot combines metadata with managed asset availability. Missing assets keep the journal card and offer Import to read; Remove is offered only for available managed EPUBs.

Normal desktop startup now wires `ReaderSessionHost` to `SessionTracker` and the SQLite checkpoint sink. The host samples an explicit wall clock and monotonic uptime once per second, gated by a ready, visible, focused reader and power/lock state. Missing or failed power/input observation stops at the last trusted sample and surfaces a tracking error. Hidden integration-test mode skips real automatic observation; host lifecycle tests inject clocks and power events.

Trustworthy gaps are at most5seconds; wall/monotonic disagreement over2seconds or rollback enters a clock hold, and a durable watermark prevents replay across restart. Counted time becomes uncertain after1200seconds without observed input. Checkpoints split at exact15second boundaries; a matching book/source/mode can resume the same session after a pause of at most120seconds without crediting the pause. These are a bounded native-inspired timing model, not a claim of exact native equivalence. Relocation, reflow and restored position never generate pages or activity. Process crashes can lose the uncheckpointed tail.

`dailyProgress` splits tracked durations proportionally across real civil-day boundaries in the requested report timezone, including DST. `creditedSeconds` contributes to minute goals alongside manual minutes; `uncertainSeconds` is reported separately and excluded. It also exposes `automaticSeconds` and `trackedManualSeconds`; tracked time creates no page credit. Stored source timezone remains evidence, while the host explicitly supplies its report timezone. Per-book Reading records display counted and uncertain intervals; the primary Timeline remains completed books only. Manual entries remain assigned to their explicitly recorded day.

The Library preload exposes a bounded journal action API, not a database handle. Main validates the exact Library window, main frame and URL, action allowlist and input fields. It supplies the actual timestamp/timezone for completion, manual entries, ratings/reviews and goals. Caller-supplied completion clocks are rejected. No journal preload exists in the reader/publication frames. No online activity was added.

Library, Timeline and personal Reviews are separate destinations. Timeline has cover-led completed-book rows with rounded system dates and compact quarter ratings, without a Recent sorter or activity fragments. Dated manual activity lives in per-book Reading records. Review and goals editors are native HTML dialogs with keyboard labels; review/manual/goals drafts share Save changes / Discard changes / Keep editing protection for dialog dismissal and native Library-window close. Existing reader draft guards remain intact. This does not protect against process crashes or OS force termination.

The hidden Electron integration covers: import stays Library-first; completion is idempotent and uses main clock; spoofed click time rejected; quarter-star review saved; dirty review cancel/native close kept draft; explicit discard/save paths passed; zero-page12.5-minute entry and independent page position persisted; pages/annual goal updates persisted; all preexisting offline reader, reader draft-close, annotation/restart, EPUB keep-copy/Trash checks passed. Removed assets retained rating/review/manual history and Import to read. Screenshots `test/library-macos.png`, `test/timeline-macos.png`, `test/reviews-macos.png` are synthetic hidden macOS Electron captures, not Windows screenshots. Timeline/Reviews no longer display completed import reports; the library retains those reports.

Verification: the combined Node journal/desktop suite passed52tests before the added watermark-restart regression; the current34journal tests pass under Electron's embedded Node on macOS, including schema2 migration/tracking and the3mocked host tests. The latest hidden Electron host integration passed in8.48seconds on macOS. Earlier embedded-runtime results covered only the11foundation fixtures; they did not establish schema2 support. These tests do not demonstrate actual Windows focus, suspend, lock, or installer behavior. The live prototype remains untouched. Journal migration adapter/backup API are implemented but have no user-facing file-picker/preview UI yet. Completion date editing is core-only; manual-only book creation UI, activity correction UI, merge resolution, richer accessibility/platform acceptance and actual Windows runtime acceptance remain outside this bounded slice.

## Independent design review revision

Primary Timeline contains completed books only; time-only/zero-page/manual position entries remain available in each book's More → Reading records dialog and keep their goal credit. Reviews requires a nonempty written review; rating-only books remain visible in Library/Timeline. Read is the primary action, rating/review is compact, and finish/log/records/removal/transfer actions are in a secondary menu. Timeline rows include explicit EPUB covers. Rounded system type identifies shell headings and dates; book titles/prose retain serif type.

The rating editor now uses a large five-star rail matching the native42px stars/6px gaps/234px hit region. Gaps select the preceding star; pointer drag and arrow keys choose quarter steps; Home/End reach0/5; dedicated Zero and Clear keep zero distinct from unrated. It exposes an ARIA slider with spoken value/hint plus explicit increment/decrement buttons. Keyboard/AX-tree assertions passed; this is not a claim of a complete screen-reader acceptance pass on Windows.

Completed import results collapse into details and can be dismissed; dismissal survives routine snapshot refreshes. Routine status notices expire after4seconds. The full host test now checks collapse/dismissal, toast expiry, rating-only review exclusion, manual entries absent from Timeline but accessible in records, keyboard zero/unrated/quarter behavior and existing Save/Discard/Keep/native-window draft guards.

`test/journal-ui.test.mjs` creates5original synthetic EPUB fixtures and persistent synthetic journal history in a temp directory. Light/dark/narrow screenshots are under this folder's `test/curated-*.png`: Library, Timeline, Reviews, quarter-star review editor and time-only records. They use original geometric PNGs explicitly marked as EPUB covers. All windows remain hidden; no real library or prototype data is used. Actual run: macOS Electron44.4.5; curated suite passed in2.07seconds. That capture run predates the latest8.48second host regression run.

Available EPUB menus now expose Export/Import notes and reading settings through the root-owned reader-state-transfer module. The trusted main process holds its reader-operation lock throughout file picker, reader close/flush, preview, explicit replacement dialog and apply. Preview shows incoming/local bookmark and highlight/note counts and revisions, explains replacement rather than merging, and defaults to Cancel. Older states are rejected; identical states are a no-op. Export refuses overwrite. The transfer contains one exact edition's position/preferences/bookmarks/highlights/notes, not the EPUB or full journal archive. Host regression verifies export flush/close/nooverwrite, preview counts, canceled import unchanged, replacement, identical no-op and stale rejection.
