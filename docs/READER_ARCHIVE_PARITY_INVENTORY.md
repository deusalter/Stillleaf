# Portable reader and journal archive parity inventory

Source inspection: 2026-09-25. This is an implementation inventory and proposal, not a declaration that a bidirectional archive exists. No production behavior changes accompany this document.

## Existing formats and entry points

| Existing artifact | Actual contract | What it does not contain |
| --- | --- | --- |
| Native history JSON | [`HistoryArchive`](../Sources/BooksCore/Models.swift#L110): `version:1`, `exportedAt`, books, intervals, corrections, goals, events, progress, merges. [`ReadingStore`](../Sources/BooksCore/ReadingStore.swift#L38) encodes dates as milliseconds since Unix epoch. `exportJSON` writes an atomic JSON snapshot; `importJSON` validates the incoming and combined archive before transactional insertion. | Reader notes/bookmarks/preferences; publication receipts/resources/original EPUBs; cover image bytes; application preferences. `BookRecord.coverPath` is a machine-local string, not an embedded image. |
| Native SQLite backup | [`backup` / `restore`](../Sources/BooksCore/ReadingStore.swift#L276): SQLite backup API, schema version1, read-only source integrity/schema validation, then transactional replacement of journal contents. Backup can replace an existing chosen destination. | Files outside the journal database. It is not the Node SQLite schema and cannot be restored there directly. |
| Native CSV directory | [`exportCSV`](../Sources/BooksCore/ReadingStore.swift#L240): books, original and effective intervals, goals, corrections, events, progress. | No CSV importer; not a full round-trip archive. The export list does not include merges. Do not reconstruct authority from summary/effective rows. |
| Per-edition reader JSON | [`ReaderStateTransfer`](../Sources/BooksPlatform/ReaderStateTransfer.swift#L41), [Node transfer](../Reader/desktop/src/reader-state-transfer.cjs), [native validator](../Sources/BooksCore/ReaderStateValidation.swift), [Node validator](../Reader/desktop/src/reader-state.cjs): schemaVersion1, exact SHA256 editionId, revision, position, preferences, bookmarks, annotations. Includes quote/note/color and locator fragments/DOM ranges. Limit2MiB and2000 records per annotation/bookmark kind. | Journal history, reviews/ratings, original EPUB, covers, edition-to-book association. This is snapshot replacement, not note merging or cross-device synchronization. |
| Managed edition directory | [Native importer](../Sources/BooksPlatform/EPUBPublicationImporter.swift), [Node importer](../Reader/packages/publication/index.js): `<editionSHA256>/original.epub`, `resources/`, `publication.json`. Hash identity is the unchanged original ZIP. IDPF-deobfuscated extracted fonts may differ from bytes in the original. | A portable journal relation. Native receipt is an `EPUBPublication`; Node wraps its own publication model in `{schemaVersion:1,editionId,publication}`. Receipts are not interchangeable. |
| Node journal SQLite | [`store.cjs`](../Reader/desktop/src/journal/store.cjs#L7): schema2, STRICT tables, foreign keys, WAL/FULL, transactional mutations. Tables: books, editions, manual_entries, events, daily_goals, migration_sources, migration_records, tracking_intervals. `backupTo` is an integrity-verified online database backup with no overwrite. | No current portable whole-journal JSON export/import or native-history adapter. | Prototype journal JSON | [`importPrototypeFile`](../Reader/desktop/src/journal/migration.cjs): explicit import of `format:"stillleaf-journal-prototype", version:1`; maximum16MiB,10000 books,100000 entries. Exact original bytes stored by digest; namespaced source-record hashes provide idempotence and conflict detection. | Not a general archive. Finished imports retain an unknown finish date. Status/totalPages and unsupported fields survive in provenance bytes, not necessarily active Node projections. |

Native imports use `Publications`, `ReaderState`, and `Covers` beside history storage ([AppModel initialization](../Sources/BooksPresence/AppModel.swift#L185)). Node reader state is separate from edition assets ([state storage](../Reader/desktop/src/reader-state.cjs)); the desktop host opens `journal.sqlite` beside its library root ([main](../Reader/desktop/src/main.cjs)). Asset removal preserves journal and reader-state files. A full archive must inventory these stores explicitly, including states whose EPUB has been removed.

Node schema1→2 migration creates and validates a unique `.pre-v2-<uuid>.sqlite` backup before upgrading ([migration implementation](../Reader/desktop/src/journal/store.cjs#L82)). This database migration is distinct from both prototype JSON import and a future portable archive migration.

## Semantic mapping and loss risks

| Domain | Native representation | Node representation | Bridge requirement |
| --- | --- | --- | --- |
| Book identity/metadata | [`BookRecord`](../Sources/BooksCore/Models.swift#L8): id, title, optional author, source, observedAt, coverPath/source, trackingExcluded, sharingExcluded | books: book_id,title,creators array,source,recorded_at | Preserve exact IDs and original metadata. An author string is not a reversible creator-array join. Node has no exclusion/cover columns. Preserve privacy flags without enabling tracking/sharing by default. Native import metadata conflict policy uses observation time; Node createBook rejects differing identity content. |
| Edition association | `epub:<sha256>` book IDs plus [`BookMergeResolver`](../Sources/BooksPresence/LibraryView.swift#L625); [AppModel.epubEditions](../Sources/BooksPresence/AppModel.swift#L258) resolves each edition book to canonical book | editions table stores edition_id→book_id; `attachEdition` refuses a conflicting existing association | Export explicit association with provenance and retain the original merge graph. A flattened link cannot reconstruct an undoable merge. Never merge by title/author alone. |
| Tracked intervals | [`ReadingInterval`](../Sources/BooksCore/Models.swift#L42): IDs, dates, duration seconds, timezoneID, mode automatic/manual/imported, disposition credited/uncertain/excluded | tracking_intervals: equivalent IDs/times/duration/timezone, source, mode automatic/manual, disposition credited/uncertain | Rename fields/date representation without changing IDs or duration. Native lacks the interval-level source field; Node rejects imported/excluded. Preserve unsupported records in source payload until semantic support exists; do not relabel them credited/automatic. |
| Corrections | [`IntervalCorrection`](../Sources/BooksCore/Models.swift#L86): ordered originalIDs and replacement intervals, reason, date; [effectiveIntervals](../Sources/BooksCore/ReadingStore.swift#L622) consumes lineage in order | No correction table or evaluation | Keep originals plus ordered correction lineage. Importing both raw and effective intervals doubles time or triggers overlaps; exporting only effective intervals loses auditability. Native replacements require fresh identities and active originals. |
| Manual reading | Native timed manual intervals; [`ManualPageAdjustmentEvidence`](../Sources/BooksCore/ManualPageAdjustment.swift) is positive additive pages with reason/recordedAt, attached to a valid source session; page-turn evidence has its own typed model | manual_entries have a civil day/timezone, optional pages/minutes/position, note, recorded_at/provenance; no invented session boundaries | Do not manufacture a midnight session to fit a date-only entry. Native has no lossless dated-manual entry type today. Keep date precision and position separate from pages; add native model support before active conversion. |
| Progress | [`ProgressObservation`](../Sources/BooksCore/Models.swift#L24): time, page/total/fraction/location, source/reliability | Manual position plus separate per-edition reader locator; no equivalent history table | Preserve observations verbatim; a renderer locator is not reliable physical page progress or activity evidence. |
| Completion | [`BookCompletionEvidence`](../Sources/BooksCore/BookHistory.swift#L3), typed `bookCompleted` AuditEvent, optional startedAt/finishedAt, source/imported | `bookCompleted` events with matching payload fields, ISO timestamps | Closest semantic projection. Keep unknown dates null, event IDs, recorded time, imported/manual authority, and stable equal-time order. Both choose manual evidence over imported completion; neither should create a new celebration during archive import. |
| Ratings/reviews/annual goals | Typed AuditEvent payloads; null rating/review/goal targets explicitly clear previous values | Event kinds bookRated/bookReviewed/annualGoalChanged with matching payload semantics | Carry full event history, not just current values. Null clear events are significant. Native optional review text vs Node empty/null normalization needs explicit mapping. Preserve equal-time ordering. |
| Daily goals | [`GoalChange`](../Sources/BooksCore/Models.swift#L59): ID,effectiveDay,minutes,pages,createdAt,optional primaryUnit with legacy fallback | daily_goals rows: ID,effective_day,unit,minutes,pages,recorded_at,sequence | Preserve historical effective dates and order; resolve legacy native unit without losing the original field. Do not export only current preferences. |
| Audit/source data | [`AuditEvent`](../Sources/BooksCore/Models.swift#L72): detail, optional session and typed evidence; array order matters | events: seq,id,kind,book,recordedAt,arbitrary JSON payload; tracking source/reason fields inside payload | Generic appendEvent is not a native event importer or validator. Preserve detail, unknown event kinds, typed payloads, and deterministic order. Native Codable re-encoding does not retain arbitrary unknown JSON keys. |
| Merge/unmerge | [`BookMerge`](../Sources/BooksCore/Models.swift#L99): sourceID,targetID,active,date; resolver evaluates merge history | No merge graph, only edition association | Preserve inactive/unmerge records as well as active links. Do not rewrite historical book IDs destructively to make Node tables fit. |
| Provenance | Native import-source information in books/events | Exact prototype bytes and record mappings in migration_sources/migration_records | Include original bytes and hashes. Dropping mappings breaks repeat-import identity/conflict behavior. New archive imports need their own provenance namespace; do not masquerade as prototype imports. |
| Covers/assets | Native coverPath/source can reference cached manual, Apple Books, or EPUB artwork; original EPUB cover metadata is explicit | [Library store](../Reader/desktop/src/library-store.cjs) derives cover from explicit publication metadata, with a placeholder otherwise | Optional cover bytes require a content digest and book/edition/provenance relation. Never serialize an absolute path as a portable asset authority; never fetch missing covers during import. |

Native JSON merge preserves identical IDs and rejects differing same-ID rows; books have special newer-observation behavior ([mergeRows](../Sources/BooksCore/ReadingStore.swift#L767)). Node event ordering uses `recorded_at,seq` ([events](../Reader/desktop/src/journal/store.cjs#L375)). A bridge must preserve source order explicitly, especially for equal-time clears/updates. Sorting everything by UUID would change results.

## Deletion and conflict boundaries

There is **no durable cross-device deletion tombstone protocol** in either current archive. Native [`deleteSession`, `deleteBook`, `deleteAll`](../Sources/BooksCore/ReadingStore.swift#L180) physically remove data and materialize surviving correction components before purging SQLite pages. Consequently, an old archive can reintroduce records removed later; absence is not reliable deletion evidence. Node has no corresponding archive tombstone machinery. Do not claim synchronization or resurrection prevention.

Reader-state transfer currently rejects stale revisions, treats identical state as a no-op, and requires explicit replacement for differing state, with a fingerprint check after preview. Notes are not merged. A numeric revision only orders saves within the existing contract; independently edited devices can diverge at the same revision. A future merge protocol needs stable origin/revision ancestry and explicit note/bookmark deletion evidence. Until then, retain both conflicting source snapshots and leave local active state unchanged by default.

Existing source-native exports are recovery artifacts, not a security boundary for a new container: native history import currently decodes the selected JSON directly without a whole-file/count budget, and native JSON/SQLite exports can replace an existing selected destination. A new archive layer must add its own bounded validation and no-overwrite export policy rather than treating those entry points as safe generic archive APIs.

## Smallest lossless bridge: proposed stages

All names and shapes below are proposals, not implemented APIs.

1. **Versioned preservation envelope first.** Add a portable manifest with a distinct format identifier/version, producer/schema versions, export identity/time, explicit file entries with length/SHA256, and required capabilities. Include the exact native history JSON or a new deterministic Node journal snapshot containing every table's domain/provenance records. Retain original source payload bytes under a namespaced provenance area even when a supported projection is applied. Unsupported required capabilities must block activation, not silently drop data. A preservation-only import must say clearly that history is retained for round-trip/recovery but is not contributing destination totals.
2. **Reader/edition bridge before journal conversion.** Include per-edition schema1 reader snapshots and explicit edition→book associations. Missing EPUBs are legitimate; preserve their notes/association as unavailable assets. To activate a reader snapshot, require a validated publication manifest: reimport an included original EPUB or match a validated existing edition. For missing publications, retain the snapshot as opaque pending state until locators can be validated; never trust an imported receipt to authorize resources. Exact duplicates are idempotent, divergent snapshots require preview/replacement.
3. **Optional original EPUBs and covers.** Include unchanged originals by SHA256; regenerate destination receipts/resources through its own importer, including font deobfuscation. Do not archive extracted resources as an authoritative alternate EPUB or export a repacked deobfuscated ZIP under the old edition hash. Cover blobs get digests, bounded image decoding, explicit associations/provenance, and newly assigned destination paths. Assets omitted or missing must be reported, without losing journal/notes. External source files are never deleted or moved.
4. **Read-only projections for the compatible journal subset.** Start with completion/rating/review/annual-goal events and daily-goal history, with exact identity/date/order mappings and source preservation. Add uncorrected compatible intervals only after overlap/source/clock validation; unsupported history remains preserved and visibly unapplied. Do not count opaque or partially applied records. Add a native date-only manual-entry domain and Node correction/merge/progress/exclusion support before advertising whole-journal semantic parity.
5. **Bidirectional round-trip and conflict policy.** Persist source mapping/digest and per-record content hashes. Same identity/same content is no-op; differing content produces a preview conflict rather than latest-export-wins. Keep origin IDs and precision; no generated completion timestamps or title matching. Define tombstones and lineage only as a new explicit version/capability, with an opt-in privacy/retention policy, before offering sync-like deletion semantics.

A ZIP envelope is a reasonable proposed transport, but it must reuse the archive path/size/count/expanded-byte/ratio protections without assuming that EPUB `mimetype`/OPF requirements describe a journal archive. Reject traversal, absolute/backslash/ambiguous aliases, links, unsupported encryption, duplicate entries, unknown required versions, and mismatched manifest digests before any active-store mutation. Export into a new destination atomically; refuse overwrite.

Import planning should run offline against a staged copy. Close/flush affected readers and checkpoint tracking under the host operation lock; compute previews against current fingerprints. Validate all journal foreign keys, identity collisions, lineage/order, reader locators, optional assets and totals before commit. SQLite transactions do not atomically commit separate EPUB/state/cover files: introduce a durable operation manifest and recoverable staging/commit sequence, or initially ship export/verify-only plus preservation import. Take validated database/state backups first. A failure must leave active references and existing files usable; do not remove originals to recover space during import.

## Acceptance evidence required before calling the bridge lossless

- Native→portable→Node→portable→native retains exact source history/provenance and ordered correction/merge/clear records; verify effective totals before/after, including uncertain/excluded/imported intervals and equal-time evidence.
- Node→portable→native→portable→Node retains creator arrays, interval source, date-only manual notes/pages/minutes/position, edition association, prototype original bytes and mapping hashes without fabricated timestamps.
- Notes/bookmarks/preferences and DOM-range/fragments survive both directions for the same edition; divergent/equal/stale revisions produce the documented outcome. Missing EPUBs preserve pending state; present originals retain identical SHA256.
- Deletion tests explicitly demonstrate current old-archive resurrection risk until tombstone semantics are implemented. Test corrected split-session deletion and inactive merges so neither history nor privacy promises are flattened away.
- Corruption, oversized JSON/ZIP, unsupported versions/capabilities, invalid references, conflicting IDs, interrupted staging/commit and disk failure leave prior active data intact. Restart recovers or rolls back each durable operation phase.
- Prove Node schema2 and native schema1 backups remain readable by their own stores; do not confuse database backup portability with domain-format interoperability. Actual Windows filesystem/runtime acceptance remains separate from macOS test execution.

The smallest honest deliverable is a verified, versioned bundle that preserves source payloads plus reader state and optional unchanged assets, with explicit unavailable/conflicting/unsupported reports. Full active bidirectional journal parity requires the missing domain models above; a lossy conversion hidden behind an archive label would be a regression.
